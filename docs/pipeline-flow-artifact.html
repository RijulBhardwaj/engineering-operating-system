gate / decision work stage loop-back

What each box actually is

Gate 0 — Elephant / Goldfish

One session (full context) drafts the plan doc. A fresh subagent with zero shared history reviews it cold. Reject sends it back to a revision + a new goldfish, never the same one. No code starts on an unreviewed or rejected plan. architecture.md

Task decomposition / parallel streams

The orchestrator is always the one session, never a dispatched subagent (agents never spawn agents). Independent file-groups batch together; same-file tasks serialize. agent-coordination.md

QA gate, 6 layers

Static analysis, unit tests, integration tests, peer review, runtime monitoring, and the newly added live walkthrough — actually running the app and clicking every reachable state against the 44-state checklist, not just reading the diff. ai-code-qa-gate.md, ui-ux-states.md

Review Council, 7 passes + baseline

Security audit → adversarial security (different reviewer) → supply-chain → maintainability → QA/abuse-case → patch (approved finding IDs only, never find-and-fix in one turn) → final verdict: ship / ship with conditions / do not ship. The Zapier baseline (RLS, secrets, access control, server-side-only sensitive logic) folds into the security pass. release-review-passes.md

Hard PR gate

A PR cannot open until QA-gate layers 1-3 and 5 have actually run and passed locally. CI running afterward doesn't substitute. git-workflow.md

Self-optimization loop

The harness can revise its own rules via branch + PR — except a hard-excluded governance set (.claude/, policies/, CLAUDE.md, this pipeline doc itself), which can only change by going back through Gate 0. workflows/end-to-end-development/README.md
